# 2026-05-07

## DreamerV3 Env DIY Adapter

## Summary
- Added a DreamerV3 `embodied.Env` adapter for `env_diy`.
- Registered `env_diy_default` in DreamerV3's environment factory and config.
- Added smoke tests for adapter reset/step, time-limit semantics, and DreamerV3 make-env routing.

## Files Changed
- `world_model/dreamerv3/embodied/envs/env_diy.py`: new adapter from `env_diy.envs.DungeonEnv` to DreamerV3 observations/actions/logs.
- `world_model/dreamerv3/dreamerv3/main.py`: added `env_diy` task parsing and constructor registration.
- `world_model/dreamerv3/dreamerv3/configs.yaml`: added `env.env_diy` defaults and an `env_diy` config block.
- `tests/test_dreamerv3_env_diy_smoke.py`: added adapter and make-env smoke tests.

## Behavior Changes
- DreamerV3 can construct `env_diy_default`.
- Adapter exposes `image`, `vector`, `reward`, `is_first`, `is_last`, `is_terminal`, and `log/*` metrics.
- Adapter applies an external time limit as non-terminal `is_last=True`, while environment terminal states set `is_terminal=True`.

## Known Issues / Next Steps
- The smoke run verifies integration and formatting only; it does not establish learning performance.
- The current environment remains a sparse-reward, long-planning task, so DreamerV3 convergence is not guaranteed.
- Python 3.13 did not have `jaxlib==0.4.33`; the local `.venv` uses `jax==0.4.34` and `jaxlib==0.4.34`, with `chex==0.1.86` and `optax==0.2.3`.
