## Human input and monster collision cooldown

### Summary
- Added held-direction input for the pygame human-play loop without changing `DungeonEnv.step(action)` semantics.
- Added player monster-contact invincibility cooldown and small player/monster knockback on damaging collision.
- Added structured `info["event_details"]` entries for monster collision hits and cooldown-ignored overlaps.

### Files Changed
- `env_diy/constants.py`: added cooldown and knockback constants.
- `env_diy/entities.py`: added player cooldown and last-move state.
- `env_diy/input_state.py`: replaced stateless key mapping with a reusable held-input helper.
- `env_diy/game.py`: switched the human-play loop to keydown/keyup state tracking with per-frame action resolution.

- `tests/test_env_diy_env.py`: added cooldown and knockback coverage.

- `README.md`: documented held input, collision cooldown, knockback, and `event_details`.
- `DEVELOPMENT_GUIDE.md`: documented tick/input semantics and monster collision policy.

### Behavior Changes
- Holding an arrow key in `python -m env_diy.main` now produces continuous movement every frame.
- Releasing the held direction automatically falls back to `NOOP`.
- When multiple directions are held, the most recently pressed direction wins.
- `Z` and `X` remain edge-triggered button actions in human play.
- Monster contact now deals damage once, starts a one-second cooldown, and applies small knockback instead of draining health every overlapping frame.
- `info["events"]` remains backward-compatible string events, and `info["event_details"]` now carries structured monster collision details.
